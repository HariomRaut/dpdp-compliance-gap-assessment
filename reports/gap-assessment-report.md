# Gap Assessment Report – DPDP Act 2023 Compliance (Academic Simulation)

## Executive Summary
This report outlines the findings of a simulated compliance assessment performed on a fictional college‑portal’s handling of personal data. The assessment followed the methodology:

1. **Data inventory creation** – captured all personal data fields processed by the portal.
2. **Record of Processing Activities (RoPA)** – generated via `scripts/generate_ropa.py`.
3. **Gap analysis** – executed via `scripts/gap-analysis.py` using heuristic rules aligned with DPDP Act 2023 principles.
4. **Control mapping** – linked each identified gap to relevant ISO/IEC 27001:2022 Annex A controls (see `docs/iso27001-annex-a.md`).

## Scope
- **System**: College‑portal (student admission, academic records, communication, welfare).
- **Data covered**: All personal data fields listed in `data/personal-data-inventory.csv`.
- **Assessment date**: 2025‑09‑XX (simulated).
- **Assessor**: Hypothetical privacy‑engineering team (student project).

## Methodology
| Step | Description | Artefact |
|------|-------------|----------|
| 1. Inventory | Collected data fields, purpose, legal basis, source, storage, retention, sharing. | `data/personal-data-inventory.csv` |
| 2. RoPA generation | Transformed inventory into a RoPA template with extra columns for controls, risks, remediation. | `data/ropa-generated.csv` |
| 3. Gap analysis | Applied rule‑based checks for notice & consent, purpose limitation, data minimisation, storage limitation, and data principal rights. | `reports/gap-findings.txt` |
| 4. Control mapping | Mapped each gap to ISO 27001 Annex A controls to derive remediation actions. | `docs/iso27001-annex-a.md` |
| 5. Reporting | Consolidated findings into this report and a remediation checklist. | This file & `reports/remediation-checklist.md` |

## Detailed Findings
The full list of potential gaps is available in `reports/gap-findings.txt`. High‑level themes observed:

| Theme | # of Instances | Example |
|-------|----------------|---------|
| Notice & Consent | 2 | Consent‑based fields (phone, email) lack explicit source documentation (form/API). |
| Purpose Limitation | 1 | Some purposes phrased as “Communication & Notifications” and “Administrative & Shipping” could be considered separate purposes. |
| Data Minimisation | 0 | All data categories were specific; no vague “Other/MISC” entries. |
| Storage Limitation | 3 | Retention periods marked as “5 years after graduation” – acceptable; however, health information retention labeled “Duration of enrollment” may be ambiguous. |
| Data Principal Rights | 2 | Data shared with Examination Board and Medical Services lacks explicit mention of rights to access/correction/erasure. |

## Risk Assessment (Qualitative)
- **High**: Missing consent evidence – could lead to enforcement notices and fines.
- **Medium**: Ambiguous retention periods – risk of over‑retention.
- **Low**: Purpose limitation concerns – manageable via clarification of purpose statements.

## Recommendations & Remediation
See the accompanying **Remediation Checklist** (`reports/remediation-checklist.md`) for concrete actions, each mapped to an ISO 27001:2022 control.

## Conclusion
The simulation demonstrates a repeatable process for turning a raw data inventory into a compliance artefact (RoPA), identifying gaps, and linking those gaps to internationally recognised security controls. Implementing the remediation checklist will bring the college‑portal closer to full compliance with the DPDP Act 2023 while establishing a baseline for continuous monitoring.
